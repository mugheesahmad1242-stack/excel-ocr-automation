# Phone Ledger → Excel Automation

An AI-powered tool that reads photos of a handwritten mobile phone shop ledger and turns them into a structured, formatted Excel inventory file — with an instant analytics dashboard on top. Built with Next.js and deployed on Vercel.

---

## What it does

1. **Upload** one or more photos of ledger pages (drag-and-drop or file picker, mobile or desktop).
2. **Extraction** — each image is read by Gemini (vision model), which identifies every phone entry directly from the handwriting: Phone Name, IMEI, Purchase Price, Selling Price, and Profit.
3. **Excel generation** — entries are appended to a new or existing `.xlsx` file with a styled header, zebra-striped rows, currency formatting, and a frozen header row.
4. **Dashboard** — after processing, a "Create Dashboard" button reveals 6 KPI cards and 3 charts summarizing the batch (revenue, cost, profit, margin, best/worst performing phone).

## Why Gemini + OCR.space + Groq

Handwritten, cramped, multi-column ledger pages are hard for text-only OCR to parse reliably. This project uses a layered approach so it degrades gracefully instead of failing outright:

| Layer | Role |
|---|---|
| **Gemini 3.5 Flash** | Primary — reads the image directly and returns structured entries in one step (best accuracy on handwriting) |
| **Gemini 3.1 Flash-Lite** | Automatic second attempt if the primary model errors or returns nothing |
| **OCR.space + Groq** | Last-resort fallback — OCR.space extracts raw text, then Groq structures it into the same schema, used only if both Gemini attempts fail |

Every image is processed independently and in parallel, so one failed or slow image doesn't block the rest of the batch.

## Tech stack

- **Framework:** Next.js (Pages Router), deployed on Vercel
- **OCR / extraction:** Gemini API (primary), OCR.space API + Groq API (fallback)
- **Excel generation:** ExcelJS
- **Charts:** Chart.js via react-chartjs-2
- **Icons:** lucide-react
- **File uploads:** Formidable

## Environment variables

Create a `.env.local` file in the project root:

```
OCR_SPACE_API_KEY=your_ocr_space_key
GROQ_API_KEY=your_groq_key
GEMINI_API_KEY=your_gemini_key
```

| Variable | Where to get it |
|---|---|
| `OCR_SPACE_API_KEY` | https://ocr.space/ocrapi — free tier, no card required |
| `GROQ_API_KEY` | https://console.groq.com → API Keys |
| `GEMINI_API_KEY` | https://aistudio.google.com/apikey |

When deploying, add the same three variables in **Vercel → Project Settings → Environment Variables**, and make sure each is enabled for **Production, Preview, and Development** — a key added only to one environment is the most common cause of unexplained 401 errors.

## How the Excel schema works

Every run produces (or appends to) a sheet with these columns:

| Column | Description |
|---|---|
| Phone Name | Model name/label (e.g. "Y200", "Redmi A3") |
| Phone IMEI | 4-digit identifier written next to the phone name |
| Phone Purchased Price | Cost price |
| Phone Selling Price | Sale price |
| Profit | Explicit value if written, otherwise calculated as Selling − Purchased |

You can upload an existing file generated by this tool to keep appending new entries to the same sheet over time, since the app has no persistent server-side storage — each run returns a complete, up-to-date file for you to save and re-upload next time.

---

## Notes on accuracy

- Straight-on, well-lit photos produce noticeably better extraction than angled or glare-heavy ones.
- Very large phone-camera photos are automatically compressed in the browser before upload, both to speed up processing and stay under upload size limits.
- If a specific column is consistently misread, the extraction instructions live in plain English inside `pages/api/process.js` (the `prompt` variable) and can be adjusted without touching any other logic.
